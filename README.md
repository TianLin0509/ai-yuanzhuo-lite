# AI圆桌lite

Chrome MV3 网页圆桌扩展。**每个 Chrome 窗口一场圆桌：主 Tab 阅读，侧栏操作。** 三种视图共用同一份完整记录：A 单篇精读（默认）、B 双篇对读、C 回答索引；选择会自动保存。

可选成员：国内 **DeepSeek / Kimi / 豆包 / 千问 / 元宝**，海外 **ChatGPT / Claude / Gemini / Grok**，每场选 2–3 位（默认前三家）。2026-09-23 新增的六家中，ChatGPT、Gemini、千问已在真实网页（游客模式）通过同题、长回答、讨论、总结和停止；Claude、Grok、元宝待登录后验证，见 `docs/20260923-more-providers-verification-claude.md`。

当前版本 **0.5.0**（侧栏与记录页顶部显示版本号）。更新记录见文末。

新增后台机制已在登录后的三家原生浏览器完成正文长回答、多行代码、迭代及最小化闲置 330 秒后的讨论验证。豆包验证码恢复也已通过；文档卡片只能明确提示内容未提取完整，不作为正文完成。过程与边界见 `docs/20260909-deep-stress-verification-codex.md` 和本地 artifacts 实测记录。

## 使用

1. `npm ci`，然后 `npm run install:local`：构建并同步到固定目录 `C:\VibeData\Extensions\AI-Yuanzhuo-Lite`。
2. Chrome 扩展管理页开启开发者模式，**只需一次**“加载已解压的扩展程序”选这个固定目录。之后每次合并都会自动同步到这里，界面顶部出现“更新到新版本”，点一下原地重新加载；扩展 ID、历史记录和各窗口的圆桌都保留，主页面会在原窗口自动重新打开。本轮进行中时不能更新。
3. 点击扩展图标打开侧栏，用“选择成员”选 2–3 位，点击“连接成员网页”，分别完成网页登录。未登录的网页会在发送前明确提示，不会发出提问。
4. 侧栏顶行是这场圆桌的标题和“记录 / 历史 / 新建 / 关闭”。点“记录”进入本窗口的主 Tab。在侧栏输入问题并选择独立迭代、工作流、观点讨论或队长总结。
   - 独立迭代：原文同时发给每位成员，各自在自己的对话里回答（第一轮提问也用它）。
   - 工作流：按“顺序”一行排好的次序依次回答（↑ 提前一位）。第 1 位只收到你的问题，之后每位收到“问题 + 前面各位的完整回答”。某位出错时工作流停在那里，可重试、重新提取或跳过；跳过后继续，后面的人看不到被跳过者的内容。“停止本轮”连同排队的成员一起停。
   - 发送时若有成员还没连接网页，会先提示“连接网页”；网页要求登录、验证或额度用完时，成员行直接给出“打开网页”。
   观点讨论和队长总结会在输入框上方用灰底显示预设提示词，其他成员的回答统一显示为“队友1的回答”“队友2的回答”等占位；白色输入框是你自己的补充，发送时附在预设之后。“编辑”可修改预设（对之后所有圆桌生效，必须保留材料占位），“恢复默认”回到内置版本。
5. 主界面顶部选择 A/B/C；左侧时光机显示原始问题和提问时间。回看历史不改变侧栏的最新发送基准，旧观点可通过“引用到下一轮”带入草稿。
6. “新建”有两种：在本窗口新建（先关闭当前圆桌和它的 AI 网页，记录保留）或在新窗口新建；新圆桌按最近一次的成员自动打开各家网页。“关闭”只关闭这场圆桌打开的 AI 网页，记录留在历史里。
7. “历史”列出所有窗口的圆桌，按最近提问时间分组（今天 / 昨天 / 近 7 天…），显示“12分钟前”这类时间、轮数和成员。“本窗口打开”或“新窗口”会找回该圆桌并打开当时各家的对话网页；网站打不开原对话（未登录、对话已删除）时，成员行会说明，下一轮在新对话继续。已在其他窗口打开的圆桌只能切过去，不会重复打开。从未提问过的空圆桌离开窗口后不保留。

一个圆桌为每家成员绑定本窗口内的独立标签页和对话 URL。“原网页”打开所选记录对应的 URL，不修改当前成员绑定。侧栏关闭后，主 Tab 下方提供同一份草稿的操作区；重新打开侧栏时自动隐藏，避免两处输入。跨窗口发送被拒绝，移走成员页时需移回或停止后重新连接。

## 首版功能

- 独立迭代（并行）、工作流（串行接力）、观点讨论、指定队长总结。
- 某位成员出错被跳过后，下一轮照常进行：它网页输入框里残留的、本圆桌自己没发出去的提问会被清掉，不会挡住后续轮次；用户自己在网页里写的草稿仍会拦下不覆盖。
- 观点讨论沿用 AI-Arena 自由辩论的主提示和轮次引导，每家仅收到其他成员上轮的完整回答。有不完整回答时须先提取或核对，避免漏转发；队长总结可收集已有完整回答，并标明来源轮次。
- 逐成员状态、完整 Markdown / 代码、复制、重新提取、重试发送、跳过、停止。
- 会话持久化、轮次回看、完整 Markdown 导出、主动删除历史；关闭、在本窗口新建、从历史找回到当时的网页对话。
- 讨论与总结的预设提示词可见、可编辑，用户补充附在预设之后。
- 网页返回不确定时不会自动重复发送；长时间无结束证据时提示用户核对。
- 重新提取核对本轮提问身份；切换到其他网页对话时停止采集。历史轮次只能回看，不会覆盖成最新回答。
- 虚拟列表按本轮提问定位回答，回收掉的部分回答不会被当作完整答案；豆包文档卡片明确提示内容未提取完整，可在新一轮要求直接回复聊天正文。
- 只向被选中的网页按需注入，完成后释放 Observer 和读取定时器。
- 后台提取复用旧 AI-Arena 的 Chrome 调试唤醒与焦点模拟。每轮开始时启用，结束/停止时释放，恢复网页原有回收设置；不自动切换到前台。

回答期间 Chrome 会显示调试提示条，这是本轮后台支持；取消提示或打开开发者工具可能中断该连接，圆桌会提示核对原网页并重新提取。启用失败会阻止该成员发送，保留失败原因，不静默退回缺少后台支持的模式。公司浏览器策略可能不允许 debugger 权限。

PPT、token 统计、主题库、全站调度补丁、DNR、远程脚本、API 模型调用均未引入。

原文超过 120,000 字符时整次请求明确拒绝，不截取部分发送。最多保留 200 场本地圆桌（unlimitedStorage，不受 10 MB 限制），达到上限需用户导出并主动清理。容量不足也会明确报错，不自动删除答案。

## 验证与真实浏览器

```powershell
npm run check
npm run browser:live
```

`check` 覆盖构建、全部源码语法、`tests/*.test.mjs`、`tests/extension.mjs`、`tests/desktop.mjs`、`tests/native-desktop.mjs` 以及无默认焦点模拟的 `tests/native-background.mjs`。浏览器测试使用受控网页验证消息链路、完整性、恢复与资源释放，不能宣称真实站点已通过。

离线检查覆盖草稿重放、引用和发送清空的 revision 边界、窗口关闭中的发送、三种阅读视图及原生后台对照。长时后台受控检查可运行 `node tests/native-background.mjs --long-hidden`。此次桌面改版没有修改站点 DOM 适配器；真实网站测试仍以各自日期的记录为准，公司网络、长会话的 CPU / 内存改善尚未量化。

`browser:live` 直接启动独立、可见的 Chromium，Playwright 仅以 `noDefaults: true` 附着，不为网页开启测试用焦点模拟或禁用后台节流。登录由用户在浏览器中完成；脚本不读取、导出或提交 Cookie。新 Profile 存放在 `C:\VibeData\BrowserProfiles\AI-Yuanzhuo-Lite\live-native`，此前的 `live` 原样保留。自动化调试端口仅绑定 127.0.0.1，端口和 PID 写到忽略的 artifacts；正式扩展使用 chrome.debugger，不要求以调试端口启动日常 Chrome。

浏览器会保留给人工登录和后续实测。重新构建后，先确认没有进行中的圆桌，再通过扩展管理页重新加载扩展并刷新已连接网页。

首版 Playwright 浏览器的非活动标签页报告可见，曾造成后台验收偏差，见 `docs/20260909-peer-prompts-verification-codex.md`。现在必须以原生隐藏页面为起点，验证由扩展自身启用调试后恢复更新、结束后恢复隐藏；这不构成系统休眠、断网、验证码或公司策略限制下的成功承诺。方案调研见 `docs/20260909-background-research-codex.md`。

## 开发流程

本仓库接入 project-prep v0.1.0。初次引导提交之后执行 `node scripts/setup-project.mjs` 启用钩子；后续实现使用独立 worktree 与独立 `npm ci`，不使用依赖 junction。

- `.agents/AUTHOR.md`：实现与自测。
- `.agents/MERGER.md`：独立审查及绑定完整 SHA 的合并。
- `.agents/TESTING.md`：离线与真实账号验收边界。

不要在启用钩子后的主工作目录开发。不要从生产 Chrome Profile 复制 Cookie，也不要对生产 AI Hub 做进程操作。
