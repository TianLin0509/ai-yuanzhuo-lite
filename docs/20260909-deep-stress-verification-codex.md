## 实测及独立复核推动的修复

1. 豆包验证码后由临时会话 URL 转正式会话：只允许带 UUID 消息键及文本哈希的重新提取例外，发送、普通行号及正式对话切换仍拒绝。
2. 豆包将有序列表序号画成 CSS 计数器：在克隆节点中恢复列表数字，保留正文中有意义的数字，原网页 DOM 不被修改。
3. DeepSeek 虚拟列表移除旧消息，导致可见数量不增甚至下降：优先使用站点消息键定位本轮提问。
4. 豆包文档卡片不能代表全文：明确不完整状态，不扩展文档/PPT 功能。
5. 虚拟列表重新挂回旧答案或移除部分答案：候选与缓存完成路径均核对节点仍在 DOM 且位于本轮提问之后，保留部分文本但不误判完成。
6. 重载清空临时租约日志：用 storage.local 持久化原回收策略及 targetId；每次清理及中断消息核对页面身份，查询失败保留日志并提示，写入原值失败阻止修改网页。旧候选尚未发布，其已丢失日志不能凭当前 false 推断回 true，本轮仅按事前实测初值清理测试副作用，另记 policyRepair。
7. Kimi Lexical 单次长粘贴自动转附件：以最多 1000 个 Unicode 字符的小段连续填入一个编辑器，全文完成且与原文一致后只发一次；组装期间可停止。当前编辑区已有附件时明确拒绝发送，保留附件，不影响历史回答中的文件。

主要故障先断言复现失败，再修改实现，并补充停止及 Unicode 边界验证。离线入口 `npm run check` 覆盖 44 项测试、10 组真实 MV3 fixture 链路和原生隐藏对照；最终命令结果与独立 Merger 绑定 SHA 的结果在本地交付报告中单列。本文不是独立审查 PASS。
