## 通用改动

- 适配器配置化：代码块语言标签、需排除的思考 / 引用 / 推荐节点、回答节点自身的完成标记、未登录标记（发送前拦截，发送后出现注册墙也立即提示）。

- 代码块去掉站点渲染的行号与末尾多余空行。

## 2026-09-24 追加：逃生通道、原地更新与 AI-Arena 对照

用户报告豆包在第二轮讨论卡在“网页输入内容与原文不一致”、重试无效、在网页手动发送后无法被识别。复现与修复：

- 粘贴实验：纯文本粘贴时豆包丢掉全部空行；按扩展的方式（同时带 HTML）6917 字逐字一致。用户那次的原文无法复现，修复覆盖整类情况：比较时只容忍空行与行尾空格，任何可见字符缺失或改变仍拒发，并报出第一处差异。
- 点击发送前的失败标为“未发送”，重试无需重复确认；输入框里残留的恰好是本轮原文时直接复用，残留他人草稿仍拒绝。
- “重新提取”对所有非进行中成员可用。网页最新提问对不上本轮时，弹窗展示该提问，用户确认后才读取并标注“未核对提问原文”。
- 豆包文档卡片 2026-09-24 改为 `artifact_block`，旧识别失效导致只拿到 121 字开场白却标为完成；已加入识别，改为“内容未提取完整”。
- 真实豆包网页验证：他人草稿被拦（未发送）→ 换成本轮原文后重试直接发送，网页上提问只出现一次；网页手动发送后重新提取弹出网页最新提问，确认后读到回答。

原地更新：用户 Chrome 固定加载 `C:\VibeData\Extensions\AI-Yuanzhuo-Lite`；合并后 `afterMerge` 执行 `scripts/install-local.mjs` 同步（只写带标记的目录、不跟随链接、`build.json` 最后写入）。扩展读取磁盘上的 `build.json`（已实测解压扩展读取的是当前磁盘内容）发现新版本，界面出现“更新到新版本”，无进行中轮次时 `chrome.runtime.reload()`。重载后按本地镜像的窗口归属在原窗口重新打开主页面；重新认领窗口时优先保留原绑定的标签页（旧逻辑只按 URL 匹配，会在同一窗口多个首页标签里选错）。真实浏览器验证：同一会话、同一窗口、三家绑定标签页 ID 不变，更新后不再提示。
