# 0.5.0 鲁棒性与易用性 · 验证记录（2026-09-29，claude）

## 改动

| 用户会遇到的情况 | 0.5.0 之前 | 0.5.0 |
| --- | --- | --- |
| 某家没登录、要验证或额度用完 | 发出后才报错 | 连接网页后后台只读检查，成员行直接显示“需要登录 / 需要人机验证 / 额度已用完 / 网页未就绪”并给“打开网页”；发送前再提示一次，可直接发送（其他成员照常） |
| 回答慢还是卡住，看不出来 | 只有“等待回答” | 显示已用时间；发出 90 秒仍没开始回答时提示网页可能卡住 |
| 离开一阵后 Chrome 回收了成员网页 | 报“网页已被 Chrome 回收，请先打开原网页恢复” | 发送前在后台原地重新载入，不切换标签页 |
| 刚打开的网页还在加载 | 立刻报“未找到可用输入框” | 最多等 8 秒 |
| 刚恢复的已保存对话 | 历史还没显示就记基准，之后“无法确认本轮提问的位置” | 等历史消息显示出来再记基准 |

体检只读：只查找元素，不输入、不点击。

## 真实网站（已执行，AI Hub 登录资料副本，屏幕外窗口）

- 连接 Kimi + DeepSeek + ChatGPT：Kimi 显示“额度已用完”（网站真实额度用完，提示在输入框出现后约一秒才渲染，因此检查在找到输入框后再等 2 秒），另两家正常。
- DeepSeek 标签页被 Chrome 回收后发送：后台重新载入（未切到前台）后完成；首次暴露“历史未显示就记基准”的问题，修复后用 `chrome.tabs.discard` 再次回收复测，完成且答案正确。
- 回答中成员行显示“正在回答，55 字 · 9秒”。
- 排查中 ChatGPT 两轮停在“等待回答”：根因是测试浏览器此时打不开 chatgpt.com（新开的页面停在空白页等网络），不是扩展问题；这正是新增 90 秒提示要覆盖的情形。
