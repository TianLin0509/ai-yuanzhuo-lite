# 初步实现范围

用户于 2026-09-09 选定 Mock A，并明确首批使用 DeepSeek / Kimi / 豆包做真实网页登录实测。

主网页来自站点自身，扩展只提供一个右侧圆桌界面。点击成员卡片展开回答；点击原网页切回绑定的 AI 标签页。当前没有 B/C 两套布局，也没有 PPT、统计、主题等模块。

## 当前架构与边界

- 侧栏：折叠卡片不渲染全文；展开后，流式显示纯文本，终态再渲染本地 marked + DOMPurify 处理的 Markdown。
- Service worker：每场圆桌单独持久化；发送前写入意图与锚点，逐请求编号拒收迟到和乱序事件。
- 网页：仅按需注入 ISOLATED world。MutationObserver 只标记变化，合并读取；低频 fallback 仅在活动请求期间存在。结束时断开并释放 DOM 引用。
- 结束：结合停止按钮、当前回答与完成按钮；没有可靠证据时要求用户核对，不能用短时间静默猜作完成。
- 恢复：只检查是否仍有对应页面任务；不会在 worker 重启后自动重复发送。读取恢复保留原回答锚点。

初始方案只允许三家域名的 host 权限；无 MAIN、debugger、DNR 或远程代码。2026-09-09 用户明确要求优先复用旧版后台调试方案，现增加仅本轮使用的 debugger 唤醒/焦点支持，详见 `20260909-background-research-codex.md`。MAIN、DNR 与远程代码仍不引入。alarms 用于活动轮次和未完成资源释放的恢复检查，全部结束时清除。

## 必须现场验证的事项

真实 DOM 的发送与完成按钮、网页登录/验证弹窗、首次生成后的 URL 绑定、内容编辑器的原文保真、深度思考、后台标签页响应、完整代码/长文提取。公司环境的性能改善仍需在公司机器测量，不能拿 fixture 速度推算。
