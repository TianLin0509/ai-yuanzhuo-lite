# 圆桌管理与预设提示词 · 验证记录（2026-09-27，claude）

## 改动

| 用户意见 | 实现 |
| --- | --- |
| 侧栏顶部品牌行多余 | Chrome 原生侧栏标题栏无法去掉；删除扩展自带的“◈ AI圆桌 / 打开记录”行，换成本场圆桌标题 + 记录 / 历史 / 新建 / 关闭 |
| 模式按钮下方留白，看不到实际发出的提示词 | 观点讨论、队长总结在输入框上方灰底显示预设，其他成员回答统一显示为“队友1的回答”等占位；白色输入框为用户补充，发送时附在预设之后（原先讨论模式补充放在最前，已改为与显示顺序一致）。预设可编辑、校验必须保留材料占位、可恢复默认，对之后所有圆桌生效 |
| 历史只见本窗口、无时间 | 历史列出所有窗口的圆桌，按最近提问时间分组（今天 / 昨天 / 近 7 天 / 近 30 天 / 更早），显示“N分钟前”、轮数、成员；标出“当前”“在其他窗口” |
| 新建给两个选项 | 本窗口新建（先关闭当前圆桌及其 AI 页，记录保留）/ 新窗口新建；新圆桌自动打开成员网页 |
| 关闭圆桌 | 只关闭本圆桌打开的 AI 页（地址尚未提交的新开页也算），绑定只保留对话地址；窗口里放一场空圆桌。从未提问的空圆桌离开窗口后自动丢弃 |
| 找回旧圆桌 | 历史“本窗口打开 / 新窗口”在保存的对话地址重开各家。网站打不开原对话时：后台观察地址 60 秒，跳到新对话页即在成员行说明并改在新对话继续；若观察期后才跳，发送前拦截，不发送、说明原因，点“重试发送”在新对话继续 |

另：保存上限 30 → 200 场并申请 unlimitedStorage；同一窗口的切换（关闭 / 新建 / 找回）逐个执行，连点两次不会留下孤儿标签页。

独立审查发现两处竞态，已修复并补回归测试（旧代码下均失败）：
- 两个窗口同时找回同一场圆桌：原先输的一方先丢了自己成员页的登记再报错，留下无人管理的标签页。现改为先原子占用窗口，成功后才动标签页与登记。
- 同一窗口“发起一轮”与“关闭/新建/找回”同时发生：原先忙碌检查可能读到旧状态，关掉正要发送的标签页。现两者在同一窗口队列里排队：关闭要么看到新一轮而拒绝，要么先完成、随后的发送被拒绝（“这个窗口已换成另一场圆桌，本次没有发送”）。

## 发现的测试环境问题

- 扩展自己 `chrome.tabs.create` 的标签页首次加载早于 Playwright 路由拦截，会连到真实网站。roundtables.mjs 已用 `--host-resolver-rules` 屏蔽；desktop.mjs 与 extension.mjs 仍有同样泄漏（它们多数随后用 goto 重载，影响有限），未在本次修改。
- 已加载的无头浏览器重启后仍运行旧的扩展 service worker，改代码后需扩展重载（chrome.runtime.reload）才生效。
