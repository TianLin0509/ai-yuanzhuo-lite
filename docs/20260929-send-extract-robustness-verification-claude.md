# 发送与提取鲁棒性（ChatGPT 为主）· 验证记录（2026-09-29，claude）· 0.3.1

实测环境：AI Hub 登录资料的副本（`C:\VibeData\BrowserProfiles\AI-Yuanzhuo-Lite\hub-copy`），正式版 Chrome，窗口在屏幕外；ChatGPT 当前档 Medium，Gemini Flash-Lite，千问快速，DeepSeek 默认，Claude 默认（菜单在屏幕外窗口不可操作）。

## 查到的原因

| 现象 | 实测到的原因 |
| --- | --- |
| ChatGPT 下一轮报“该网页有尚未发送的内容”、提问填错地方 | 回答里的邮件等“文稿块”是可编辑的 ProseMirror 编辑器（“Start writing”），在页面里排在底部输入框（“Ask ChatGPT”）之前。旧规则取“第一个 ProseMirror”，会选中它。受控页复现：旧规则正是报这句 |
| 编辑旧提问时也有一个“Send” | 旧规则取页面上第一个匹配的发送按钮，可能点到它 |
| 提取出“Email / Connect email / Recipients”等界面文字，邮件主题丢失 | 文稿块自带页眉按钮与主题输入框；ChatGPT 在块上另存了一份干净的正文（`data-markdown-copy-text`，即它“复制”按钮用的内容），主题在单独的框里 |
| 偶发整封邮件没被提取 | 结束信号出现后，文稿块会重新挂载；后台标签页渲染更慢，正文可能晚于结束信号。前台时序实测正文全程都在；后台两次复测均完整，最初那一次未能复现，按此原因加防护 |

## 改动

- 输入框：跳过落在回答或提问里的可编辑区；多个候选时取旁边有发送或停止按钮的，否则取屏幕最下方的；都被排除时退回原规则。ChatGPT 优先按“Ask ChatGPT”标签找。九家通用。
- 发送按钮：先在输入框所在区域里找，找不到再全局找，并排除消息里的按钮。
- 回车兜底：实测脚本回车能发送的五家（ChatGPT、Claude、Gemini、DeepSeek、千问），按钮 2 秒内不可用就按回车；其余站点仍然只点按钮，找不到就报错。无论点按钮还是按回车，之后都由同一套逻辑核对新提问是否出现、回答是否开始，核对不上就标“发送待确认”，不自动重发。
- 文稿块：用 ChatGPT 自带的正文副本，前面加粗附上主题；页眉按钮与建议按钮不进入正文。正文尚未填入时最多等 30 秒再判定完成。

## 回车能否代替按钮（实测）

| 站点 | 脚本回车 |
| --- | --- |
| ChatGPT、Claude、Gemini、DeepSeek、千问 | 能发送 |
| Kimi | 额度用完，无法判断 |
| 豆包、元宝、Grok | 未登录，无法判断 |

没有把回车改成首选：按钮的可用状态本身说明网站已接收到文字、准备好了；回车在少数站点可能只换行，或被输入法组合状态吞掉。所以按钮优先，回车只在按钮不可用时补上，并照常核对结果。
