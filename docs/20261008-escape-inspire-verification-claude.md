# 0.6.0 逃生通道、互相激发与界面改版 · 验证记录（2026-10-08，claude）

## 改动

| 用户会遇到的情况 | 0.5.0 | 0.6.0 |
| --- | --- | --- |
| 某家卡住、出错或答偏 | 只在出错时出现部分按钮（重新提取 / 重试发送 / 跳过），回答中只能整轮停止 | 每位成员卡片始终显示 重新提取 / 重新发送 / 跳过 / 换人；回答中也能重新提取（只重开读取）或重新发送（先停止再发，需确认） |
| 已完成的回答想让它再答一次 | 不允许（“该轮已经结束”） | 确认后重新发送，旧回答保留为“之前的回答”，记录页可展开查看，导出也包含 |
| 工作流前面的人卡住 | 只能跳过它 | 排队中的成员可“重新发送”= 立即发送，用当下已有的前面回答组装 |
| 某家额度用完 / 登录失效 | 换人只在本轮结束后生效，本轮这一席空着 | 换人随时可用：本轮还在排队、回答中或出错时，新成员立刻接手同一位置并收到同样材料；已完成、已跳过或整轮停止时从下一轮起换 |
| 想让各家互相借鉴、各自变得更好 | 只有观点讨论（互挑错 / 取长补短） | 新增“互相激发”，位于观点讨论和队长总结之间，提示词与 Android 0.19.0 逐字一致 |
| 界面 | 单行列表 | 成员卡片（各家标识色块、状态色条）、五个模式下方一句话说明、轮次彩色标签、回答页标签带头像、对读与索引卡片化 |

## 真实网站（已执行，2026-10-08，AI Hub 登录资料副本，屏幕外窗口）

可用成员：DeepSeek、千问。Kimi 网页真实提示“额度已用完”；豆包、元宝需重新登录；ChatGPT、Gemini 此时网络不通，均未覆盖。

1. DeepSeek + Kimi 独立迭代：DeepSeek 完成 126 字；Kimi 真实报额度用完、未发送。
2. 对 Kimi 点“换人”→ 千问：千问 12 秒内接手本轮并完成 244 字，Kimi 记为“已跳过 · 已换成 千问”。
3. 互相激发（DeepSeek + 千问）：两家各收到对方完整回答、不含自己，也不含被换下的 Kimi；DeepSeek 518 字、千问 391 字，均给出升级后的完整回答并说明受到的启发。
4. 回答中对 DeepSeek 点“重新提取”：读取重开，网页继续生成，没有重复发送。
5. 对已完成的 DeepSeek 确认“重新发送”：新回答 550 字，之前的回答保留 1 份。
6. 对千问“跳过”后“重新提取”：恢复为已完成 391 字。
