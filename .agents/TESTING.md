# 验证边界

`npm run check` 是离线合并总入口，失败退出非零。它运行构建、每个 src/*.js 的语法检查、所有 tests/*.test.mjs 和 tests/extension.mjs。

- core.test.mjs：原文完整性、讨论材料、上下文超限拒绝、重复发起保护、迟到/乱序/跨标签页事件、合法平台、完整导出。
- workspaces.test.mjs：窗口唯一归属、并发重开、URL-only 迁移、陈旧 tabId、关闭窗口和成员移窗的拒绝边界。
- desktop.mjs：加载真实 MV3，以受控历史和站点页面验证 A/B/C、默认视图、历史引用、双窗口隔离、草稿和窗口重开、后台重启及迟到状态回包。这些记录不是真实 AI 生成结果。
- native-desktop.mjs：真实 Chrome SIDE_PANEL 上下文、所属窗口、唯一可见操作区、多行草稿、后台重启及原生侧栏关闭；不向 AI 网站发送消息。
- extension.mjs：真正加载 MV3 扩展，用受控三站 HTML 验证 UI → service worker → 内容脚本 → 网页 DOM → 存储 → UI 的链路；检查资源释放和未选中网页零注入。
- fixture.mjs 是网页数据提供器，不是独立测试入口。
- background-support.test.mjs：Chrome 调试支持的请求归属、取消、失败传播、完整恢复日志与回收设置还原；清空 session 后的 local 日志恢复、target 身份变化、查询/落盘失败必须覆盖。background.test.mjs 还覆盖取消/停止与异步注入的发送边界竞态，以及旧任务恢复不得向复用 tabId 的新页面发送停止消息。
- captcha-recovery.test.mjs：豆包验证码后临时 URL 转正式会话的受限重读、Markdown 有序列表数字身份、DeepSeek 虚拟列表消息键、文档卡片不冒充完整答案、旧回答重新挂回与部分回答节点回收不得误判完成。
- input-ownership.test.mjs：Kimi Lexical 长文本分段填入同一个编辑器，最终按完整原文仅发送一次；Unicode、空行与缩进保留；当前编辑区附件阻止发送，历史附件不误阻挡；组装期间停止后不得继续填入或发送；等待按钮期间出现附件、更换编辑器或修改正文时，点击前再次同步拦截。
- escape.test.mjs：网页丢掉空行时仍完整发送一次，少一个字仍拒发并报“未发送”；输入框里残留本轮原文时重试直接复用、残留他人草稿仍拒绝；网页里手动发送后，提问能对上就继续读取，对不上时返回网页最新提问供用户确认，确认后才读取并标注未核对；豆包文档卡片不冒充完成。
- providers.test.mjs 另含：DeepSeek 深度思考只读正式回答且读出“深度思考”模式；豆包新对话只有过渡输入框时等真正编辑器出现再输入（去掉等待则该用例失败）；Gemini 读出当前模式。core.test.mjs 覆盖两种讨论风格分别计轮、提示词要求正文写完整、队长总结开场白识别，以及预设模板的占位展示、自定义、必须保留材料占位和单次替换。providers.test.mjs 含 ChatGPT 2026-09-27 新界面（“Send”按钮、…:user/…:assistant 回合、无 <pre> 的代码块、完成后才出现的 Regenerate 操作栏、模式读取）。core.test.mjs 覆盖工作流顺序校验、逐位组装、失败暂停与跳过继续、超长明确拒绝。background.test.mjs 覆盖：保存的对话被网站跳回新对话时不发送、说明原因，重试在新对话继续。同一窗口同时发起一轮和关闭圆桌时，要么拒绝关闭，要么不发送。
- roundtables.mjs：加载真实 MV3，用受控历史验证：旧索引补齐成员与时间；“关闭”只关本圆桌打开的 AI 页（不动用户自开的同站页）、保留记录与对话地址；历史分组与相对时间，“本窗口打开”在当时的对话地址重开三家，网站跳回新对话时成员行说明并改在新对话继续；本窗口新建自动打开成员；同时两次“新建”依次执行不留孤儿页；两个窗口同时找回同一场圆桌时只有一方得到，另一方保留自己的圆桌和成员页；其他窗口的圆桌只能切过去；预设提示词的统一占位、编辑校验、实际发送与恢复默认；侧栏工具行 360px 不溢出。该测试用 DNS 屏蔽真实站点：扩展自己新开的标签页首次加载早于 Playwright 拦截，不屏蔽会连到真实网站。
- workflow.mjs：加载真实 MV3 与受控三站：未连接就发送先提示连接；工作流按自定义顺序依次发送，第 N 位收到问题与前面全部回答；中间一位发送失败时后面的成员保持排队、未收到任何内容，跳过后继续且不含被跳过者；下一轮全部完成，被跳过者输入框里残留的本圆桌旧提问被替换（去掉清理逻辑时该步失败）；停止工作流连同排队成员一起停。
- providers.test.mjs 另含 ChatGPT 2026-09-29 两页：回答里有可编辑邮件块（排在输入框之前）、旧提问里有编辑框自己的“Send”、新回答的邮件正文在结束信号之后几秒才填入——只能填底部输入框、只点底部发送、等正文到齐再完成、提取用网站自带的纯文本副本并带主题、排除“Email / Connect email / Recipients”与建议按钮（换回旧的输入框查找时该用例失败）；以及没有可用发送按钮时按回车发送并照常核对。
- workflow.mjs 另含：连接网页后的只读体检（受控页插入额度提示后成员行显示“额度已用完”与“打开网页”，发送前提示且不发送；移除后重新连接恢复正常）、回答中成员行显示已用时间。providers.test.mjs 含输入框晚 1.5 秒才出现的页面（去掉等待时失败）。background.test.mjs 含被 Chrome 回收的成员页在发送前后台原地重新载入。
- members.test.mjs：侧栏成员行内换人（跳过或失败的成员直接显示）、悬停移出（最少两位）、未满三位时添加；只列圆桌外的 AI；换人保持位置并记为新建圆桌默认；跳过的成员不阻塞观点讨论。
- native-background.mjs：原生 Chromium + noDefaults 附着，未启用时三家隐藏且受控 rAF 停止；由扩展自身启用后后台三家完整生成；结束恢复隐藏并释放调试连接，非成员对照页不受影响。

Playwright 在 Windows 优先使用已有 `C:\VibeData\BrowserCache\playwright`；其他环境按 Playwright 默认浏览器目录，需要先 `npx playwright install chromium`。

## 必须另做的真实验收

用户登录要测的成员网页后（ChatGPT、Gemini、千问可用游客模式，但登录后结构可能不同），逐站确认输入框、发送按钮、回答容器、完成信号和会话 URL。tests/providers.test.mjs 的受控页面只复刻当日结构，同样不能代替真实网页。至少覆盖同题并行、第二轮追问、讨论、总结、单家重读、停止、长回答/代码、后台页和侧栏重开。人工登录未完成或其中某站未测时必须明确标注。

隔离 fixture 能证明程序内部行为，不能证明第三方网页当前兼容，也不能证明公司机器上的性能提升比例。

后台验收必须记录 Chrome 的标签页 active 状态以及页面原生 visibilityState / wasDiscarded，不能只凭标签未被选中就判定已测试隐藏页面。Playwright 的焦点模拟可能使非活动页面仍报告 visible；即使去掉禁用后台节流的启动参数，也不能据此宣称普通浏览器的后台可靠性通过。必须原生启动浏览器，后续 CDP 附着使用 noDefaults: true，避免添加测试工具的焦点模拟。仅当先证实原生 hidden，再由正式扩展自己的 chrome.debugger 变为 visible，且终止后恢复，才可证明本次获准的后台支持机制。不能在测试脚本额外发送 focus emulation 命令来帮助通过。

成员和非参与对照页均使用 Chrome 原生 `tabs.create({active:false})` 创建。实测即使 noDefaults 附着，Playwright `context.newPage()` 创建的页面也可能在扩展启用前保持 inactive / visible。必须在发送前就断言对照页 hidden、原生 rAF 不增长、没有扩展 debugger 所有权和产品脚本注入；记录 tabId / targetId，并在生成中及结束后继续检查。不能把漏验的可见对照页视作产品影响范围的证据。

`node tests/native-background.mjs --long-hidden` 提供 330 秒后台等待后的受控验证。真实三站后台、窗口最小化和调试取消恢复要另列结果；禁止把受控页面或短时测试推成真实三站长时通过。

Profile、用户对话、截图、日志在忽略的 artifacts 或 C:\VibeData；不进提交。只操作本次启动的浏览器，不终止生产 Hub，不复制个人 Cookie。
